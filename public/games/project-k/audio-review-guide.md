# Project K audio review v1

The web editor exports every clip, regardless of filters. Only `changed: true`
entries request a game change. `requestedGain` is an absolute linear gain replacing
the original SoundLevels value: 1 = 100%, 0 = mute. It is not a relative multiplier.
Preview monitor volume is local and never part of the export.

Verify `sourceFingerprint`, `sources`, each clip GUID/path/SHA256 and original gain
against the current Unity project. Report conflicts instead of overwriting newer
work. Names and IDs are immutable. Multiple files with the same AudioClip.name
share a gain because SoundLevels.Of currently looks up names, not GUIDs.

Follow project AGENTS.md. SoundLevels.asset is generated by SoundBalanceProbe.
Implement persistent authored overrides (or change that generation pipeline) so
rebalancing cannot erase the user's decisions. Do not hand-edit only the generated
asset. Keep cue volumes, pitch, SFX/group/master settings, music and audio samples
unchanged. Unreferenced files are retained for review, not automatically enabled.

`procedural-guard-pulse` has no asset GUID. Its stable ID refers to DefenseFeedback's
runtime-created clip. It only plays without CombatAudio.Active and currently
bypasses SoundLevels. A requested change needs a gain hook in that runtime path.

Check CombatAudio cues/raw clips/ambience, PlayerSkills prefab AudioSources,
LootFx, QuestBanner and the fallback after applying. Browser previews do not
replicate Unity spatial attenuation, pitch, cue volume or AudioSource clamping.
Source MP3 previews are encoded without normalization.

Catalog coverage: all non-music audio under _Game, audio reached by following
serialized GUID references from _Game assets/scenes/prefabs, SFX named by
SoundLevels and the procedural fallback. Unused third-party library sounds and
background music are excluded. A serialized reference proves a dependency,
not that a particular sound is triggered during a play session.
